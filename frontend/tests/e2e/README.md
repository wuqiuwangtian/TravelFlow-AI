# 浏览器主流程验收

在仓库根目录准备后端，在前端目录运行：

```sh
cd backend
uv sync --frozen
cd ../frontend
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
pnpm test:e2e
```

Linux 缺系统库时使用 `pnpm exec playwright install --with-deps chromium`。默认读取 `backend/.venv` 的 Python（兼容 Windows）；虚拟环境在其他位置时设置 `TRAVELFLOW_TEST_PYTHON` 为 Python 可执行文件路径。

测试自动启动 `127.0.0.1:8137` 的专用后端和 `127.0.0.1:3137` 的生产前端，拒绝复用已占用端口，结束时关闭服务。后端使用独立临时 SQLite 数据库和固定模型、检索替身，不加载 `.env`，不需要真实 API Key，也不接触个人旅行记录。测试种子接口只定义在 `backend/tests/browser_server.py`，不会进入正常应用。

当前共242个场景（原有204项业务与交互回归，加上6项共享基础、12项旅行工作区、8项正式撤销和12项 W1 高级工程检查；使用桌面与手机尺寸的 Chromium），覆盖跨轮城市推荐、结构化生成、批量记账与预约、对话修订、刷新、导出、旧文字路书整理、原位费用编辑，以及澄清承接与取消、地点候选与区域选择、导航和预算同步、断网／超时／鉴权错误恢复、后台已记账但回复丢失后的重试和分支草稿隔离；失败记账后先使用快捷建议、快捷建议再次断流及刷新后仍保留原请求号。同日同名同额消费覆盖刷新后选择、连续多项澄清、关联回款、删除保护、草稿保留、预算与导出同步。两天联动覆盖夜间延误预览、刷新后一次应用、固定预约冲突拒绝、条件修改、可选项目精简展示、取消不留部分改动、预算／导出同步及应用回复丢失后的重试。景点搬移覆盖时间轴入口、移入移出、同名选择、刷新取消、双日期展示、预算与账本编辑保留付款日、未知付款日保留、预约／未知交通保护、历史版本及导出同步和应用断流重试。旅行回顾覆盖事实模板、编辑保存、刷新恢复、重复保存、独立导出、未保存文字提示、安全转义、事实变化后保留旧文与历史隔离。旅行照片覆盖上传、重复文件去重、日期地点说明、封面、保存刷新、选择性离线图文导出、移除与历史、错误图片恢复和文字保留。AI写作覆盖草稿不覆盖原文、采用与丢弃、分别保存回忆与朋友圈文案、刷新复制、鉴权失败后手动保存与重试、素材勾选、剪贴板不可用降级及并发版本保护。旅行收尾覆盖结束保留未完成／未结算、归档搜索只读阅读和导出、结束后补记、重新开启、非主方案跳转、分叉状态隔离、相同内容保存及结束回复丢失重试。旅行生涯覆盖按会话去重、城市筛选、统计口径、只读回顾来源、补记跳转、主方案重新开启后采用结束备选、活动补记同步、全部开启后移除，以及空状态、加载失败不冒充零统计和重试恢复。常用偏好覆盖主动保存与刷新、修改、删除保留已有旅行副本和历史、默认不选用、本次对话覆盖／清空、跨窗口冲突保留输入、载入最新核对、保存回复丢失重试、选用内容变化时重选及加载失败继续规划；仅这组操作本机单例偏好的场景通过临时文件锁串行执行，其他流程仍并行。生涯照片与足迹覆盖选入照片分页和备选方案去重、未选内容不展示、用户标注不证明到访、文本转义与只读来源，地图失败保留点位、重试编号对应、活动更正后刷新与旧快照拒绝，以及照片列表和图片失败恢复、重新开启后移除而旧版本保留。地图图片成功场景使用本地测试图片，后端另以高德响应替身检查仅传确认点、不传计划路线、上限与缓存；不证明真实高德静态地图服务可用。只读高级流程覆盖从原方案进入四个真实节点、预算和实付查看无写入、来源与未知执行状态、分支／历史版本和导出对应、延迟响应切换隔离、错误版本和加载失败恢复、真实生成节点中断后原对话重试恢复，以及待澄清操作不会被节点查看应用。替身验收用于发现界面与真实接口、持久化的集成回归，不证明真实模型、搜索或地图服务的可用性。

运行失败时 `frontend/test-results/` 保留截图和 trace；CI 上传7天有效的失败证据。可用 `pnpm exec playwright show-trace <trace.zip路径>` 查看。测试结果目录已忽略，不提交数据库或截图。

## FE-0 现状盘点

独立的 `playwright.audit.config.ts` 使用同一隔离服务，串行运行 `tests/audit/` 的 20 项状态探测，不混入正常业务回归。FE-1 后已修复项增加正向断言，`pnpm exec playwright test --config=playwright.audit.config.ts` 输出截图与 JSON 到忽略的 `frontend/test-results/fe1-audit/`，保留 `docs/frontend-audit/` 中的 FE-0 历史证据。源码扫描默认输出到 `frontend/test-results/frontend-inventory/`。报告与边界见 [FE-0 盘点](../../../docs/frontend-audit/README.md)和 [FE-1 交付](../../../docs/frontend-feedback.md)，不能以探测通过宣称没有界面问题。

## FE-3 共享基础

`design-foundation.spec.ts` 使用路由替身隔离常用偏好，不改写偏好单例；核对共享按钮／导航的实际反馈、等待与失败恢复、主题基础色对比度和减少动画。此项不证明全站主题设置已完成。整套回归若遇隔离 SQLite 并发锁冲突，可使用 `pnpm exec playwright test --workers=1` 在新建测试服务中串行复核；本次 FE-3 验证采用这一方式，覆盖与边界见 [共享基础交付记录](../../../docs/frontend-foundation.md)。

## FE-3 旅行工作区

`journey-workspace.spec.ts` 检查 D3／M1 的实际布局、当前站、日期与旅中状态、直达入口和草稿保留，使用浏览器内测试 SVG 核对 P1 缩略图／完整图、失败回落及焦点。正式行为与阶段边界见 [工作区交付记录](../../../docs/frontend-workspace.md)。

## FE-3 正式规划撤销

`plan-undo.spec.ts` 经正式对话和版本接口检查最近一次规划修改的说明与撤销、等待反馈、输入草稿与焦点、真实消费保留、断流后刷新重试、并发版本冲突、修改记录查询失败与历史隔离。新版本读取稍迟于消息时，手机完成说明仍须回到视野内，初次打开的 M1 顺序保持。业务边界与完整验证见 [撤销交付记录](../../../docs/frontend-plan-undo.md)。

## FE-3 W1 高级工程

`studio-workspace.spec.ts` 检查电脑并排布局、长参数独立滚动、手机直达、草稿与正式版本隔离、独立产物、键盘移动和撤销、空间控件不位移、只读快照，以及保存等待／失败和减少动画。采用核对弹窗还需位于实际页面宽度内并能真实关闭；手机不能只用可能已被内容撑宽的 `innerWidth` 判断溢出。原 `studio-*.spec.ts` 继续核对既有节点与模板、执行、缓存、分日、定位、合并、预算和采用能力。见 [W1 交付记录](../../../docs/frontend-studio.md)。

## FE-4 比较与指南

`reference-pages.spec.ts` 核对双端各列独立加载及重试、选择上限与正常空态、迟到正文和主方案回执隔离、真实切换主方案时版本不变、分支来源、长内容与实际视口，以及指南的章节跳转、键盘折叠、减少动画和外链说明。临时数据库与现有正式接口继续验证版本和来源；特定失败和迟到响应由测试控制。见 [交付记录](../../../docs/frontend-reference-pages.md)。

## FE-4 三主题与最终收口

`theme-settings.spec.ts` 覆盖首屏、默认主题、无效值、跨标签同步、存储受限、服务不可读、服务草稿保护、三主题正式页面与对比度、真实版本不变、节点坐标与模板弹窗。`npm run check:design` 与 CI 约束正式源码的语义颜色和产品 emoji；测试数据及用户原文不受清洗。最终 316 项回归与 Windows 两端核对见 [收口记录](../../../docs/frontend-themes.md)。

## 普通主流程少操作

`ordinary-flow.spec.ts` 从推荐城市与短选择开始，覆盖历史读取失败、草稿和原位重试、迟到响应与分支隔离，以及对话记账和修改后保存回顾、结束、阅读及导出。失败只控制对应请求，版本、实付、回顾和导出使用真实本地接口；用户原文保留。见 [走查记录](../../../docs/ordinary-flow.md)。
