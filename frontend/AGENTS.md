# 前端设计约定

前端视觉与交互的用户约束及选型记录以 [DESIGN_BRIEF.md](../DESIGN_BRIEF.md) 为准，开发前先读。FE-2 已确认 A/B/C 作为设置中的可选配色主题、默认 A，电脑默认松弛密度、手机默认紧凑密度；电脑默认 D3 对话主导、手机默认 M1 今日路线。第三轮已确认 C1 轻圆角短反馈（8px／160ms）＋P1 小图辅助。第四轮已确认 R1 直接更新可撤销＋W1 画布右侧参数与产物，FE-3 开始迁移。共享规范见 [SYSTEM.md](../docs/design/SYSTEM.md)；不能用此前推荐的 D1 替代用户选择，也不能把选型确认理解成已验收全站。

- 用户要求全站统一且后续开发沿用同一风格；选型确认后复用约定的 token 与共享组件，不在新业务页面另造配色、排版、圆角和动效体系。
- 产品编写的界面文案不使用 emoji，使用项目已有的 Lucide 图标。不要擅自清洗用户输入、用户照片、历史对话或模型原始内容。
- 所有可操作按钮、图标按钮和按钮式链接要覆盖悬停、按下、键盘焦点、处理中及禁用状态；提供可感知的悬停／点击动效，并尊重减少动画偏好。画布节点的动效不能破坏拖动坐标或连线。
- 点击动效不能代替请求反馈；保留 FE-1 的原位等待、失败草稿、重复提交保护与业务幂等性。
- 电脑侧重规划与比较，手机侧重今日路线、当前站、导航和记账。不能以桌面截图通过替代手机可用性核对。
- 迁移沿用已确认的设计；UI 改造不扩大后端功能范围。R1 正式应用与撤销必须保留已有版本、账目与请求幂等性，不得使用样稿的内存模拟替代正式业务。
- 景点图片遵循已确认的 P1：固定缩略图区域，等比裁切而不拉伸；展开按原比例完整显示并限制查看框高度。未知图片尺寸不能改变路线行高；缺图／加载失败回落文字，不把补图变成用户必填任务。

- 三主题设置与本轮全站收口已交付，记录见 [frontend-themes.md](../docs/frontend-themes.md)。正式界面使用语义颜色类或 `--tf-*`；配色值只放 `styles/tokens.css`，运行 `npm run check:design`。共享样式与主题修改需核对 A／B／C、两端可读性及空间控件坐标，主题不能保存服务配置或改写旅行。
