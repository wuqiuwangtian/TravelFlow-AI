# TravelFlow AI 后续产品路线

更新日期：2026-11-16。当前能力与限制见 [阶段现状](./PROJECT_STATUS.md)，历史实现过程见 [更新日志](../../CHANGELOG.md)。本页只保留后续方向、顺序和验收条件。

## 产品目标

用户讲清需求后，系统先给出一版可使用的完整建议；有变化时继续说一句，路线、时间、预算和计划书共同更新。旅前帮助决策，旅中承接变化，旅后留下记录。

普通用户使用封装好的固定流程。高级用户可按需进入节点工程，两种模式共享同一份旅程数据。需要补充信息时集中问一个关键问题，避免让用户到处寻找未填写的字段；地点、费用、时间和资料的不确定性必须明确，不能靠编造完整性减少操作。

## 优先级与顺序

| 阶段 | 要解决的问题 | 完成后的用户体验 |
| :--- | :--- | :--- |
| 1. 主流程可靠性与对话恢复 | 失败后要重来、澄清后上下文接不上、验收依赖临时脚本 | 补一句或重试即可继续，已有输入和账目不丢、不重复 |
| 2. 相邻两天联动调整 | 夜间变化与第二天安排脱节 | 能先看到两天受影响的变化，一次应用后整体一致 |
| 3. 旅后记录最小闭环 | 旅行结束后只剩计划书和零散账目 | 生成有实际记录、照片、支出和文字的旅行回顾 |
| 4. 旅行生涯与偏好积累 | 多次旅行之间没有联系 | 查看到访城市与回忆，授权后复用明确偏好 |
| 5. 高级节点工作流 | 有经验的用户需要控制规划步骤 | 可展开和重跑节点，结果仍回到同一份旅程 |
| 6. 全面前端升级（本轮实现已收口） | 整体视觉与交互不足，多处操作反馈不明显 | 主要页面统一改造，点击有反馈，进度和结果就近可见，失败能恢复 |

已完成能力与验证边界统一见[项目现状](./PROJECT_STATUS.md)，下文保留各阶段范围与验收要求。

验收条件：晚间延误影响次日出发的场景能生成两天一致的方案；预约不被静默取消；实际账本与历史不变；冲突无法解决时不会把半份调整保存为成功。普通修改继续直接执行，涉及跨日挪动固定安排的取舍集中展示。

跨城搬移、固定安排换天、更多天联动与更完整的取舍方案按实际需求继续扩展。此阶段不代订、不自动取消商家订单，也不默认开启持续定位、天气或余票监测。

## 阶段3：旅后记录最小闭环

进度：核心闭环已完成。无需模型生成事实模板，可编辑标题和回忆、保存版本、刷新及独立导出 Markdown／HTML。未确认到访与预估费用单独标明；事实变化后保留原文并提醒核对，重复保存不增加版本，并发修改不覆盖新记录。可明确结束当前方案或重新开启，不自动补完活动、费用，也不自动附带票据、消费备注和订单资料。已接入独立旅行照片、日期地点标注、封面与选择性离线图文HTML导出，清除元数据且不把图片关联视为实际到访；照片选择和说明随版本保存，移除后历史仍可看。已接入AI回顾与朋友圈文案，默认仅发送已完成活动，回忆原文与支出汇总需勾选；照片和票据不发送。先预览草稿，再采用编辑与保存，短文可复制、不自动发布；模型失败仍可手动编辑。已实现结束时间与版本、结束后补记、重新开启、回顾列表搜索分页及只读阅读，源方案和历史保留，分叉默认未结束；会话归档不代表结束。下一步进入阶段4，先汇总可追溯的已完成活动与已记净消费，明确多方案去重规则。

- 增加“结束旅行／生成回顾”入口，汇总已完成、跳过、临时新增活动及实际净消费；未确认到访和未结算费用明确标记。
- 独立管理旅行照片，可关联日期与地点、补充说明、选择封面和移除；复用安全存储能力，但与消费凭证分开使用。
- 先提供一个完整的回顾模板：实际路线、每日片段、支出汇总、精选照片与短文；可生成和编辑朋友圈文案。
- 支持本地保存及包含所选照片的可携带导出，明确文件体积与内容范围；生成、重新生成均不改写原始旅程事实。

验收条件：一次旅行结束后能直接得到可编辑、可带走的记录；未去地点不会写成已到访；估算金额不会写成真实消费；模型不可用时仍能查看、整理与导出已有内容。分享前由用户选择照片和文字，票据及私密信息不默认进入分享内容，发布由用户主动发起。

首版聚焦单次旅行，不同时建设社交平台、自动剪辑视频或云端多人相册。

## 阶段4：旅行生涯与偏好积累

首版已完成：按会话去重当前已结束方案，展示旅行数、已完成活动、已记净消费及到访城市；按城市筛选来源，进入原版本回顾和对应分支补记。采用方案明确可查，修正、切换主方案、重新开启和删除后重新汇总。金额排除预算估算和待到账回款，城市排除交通、车站、定位起点与未确认到访；已接入选入照片回忆墙与确认坐标的静态足迹地图；照片日序按用户标注，尚无实际拍摄时间轴。记录结束时间不作为真实出游日期。

常用偏好已完成：用户主动保存、查看、修改与删除；新建前展示具体内容且默认不选用，选用时核对当前修订并复制到本次会话。本次对话可覆盖或清空，不改常用偏好库；已有旅行不受后续删除影响，不把单次愿望、日期、预算或目的地静默存为长期记忆。加载失败可直接规划，跨窗口冲突及回复丢失有保护。

照片回忆与城市足迹已完成：当前采用方案中选入的已保存照片支持分页、城市筛选和来源阅读，未选内容不自动展示；照片关联不证明到访，结束记录时间不当作拍摄时间。足迹列表只取已完成非交通活动，地图仅展示最多10个去重的确认坐标，不含计划交通线或虚构城市中心；未定位或地图服务失败仍保留实际记录，来源变化后旧地图快照被拒绝。

阶段4核心闭环已完成，阶段5已接入自由生成工程、默认模板及成稿预览采用，首批结构化工具节点已接入，个人命名模板与跨旅行复用已接入，每日景点筛选与路线顺序参数已接入，费用估算参数与分类预算预留已接入，独立景点候选池与规则分日已接入，候选定位与区域分组已接入，多路候选池合并与去重已接入，全面前端升级的本轮实现与隔离验收已完成；真实GPS跟踪、拍摄时间轴和偏好自动推断不属于本轮完成范围。

- 汇总多次已记录旅行，展示到访城市、时间、主题、花费和照片回忆，支持回到原旅行查看。
- 地图统计区分计划地点与确认到访，估算里程不冒充真实GPS轨迹。
- 用户明确同意后保存常用偏好，并可查看、修改、删除；下一次规划可复用，单次愿望不自动变成永久偏好。

验收条件：生涯汇总可追溯到每次旅行；修正、删除旅行后统计同步更新；新规划仍可覆盖已有偏好。

## 阶段5：高级节点工作流

自由生成工程首版已完成：新增输入／检索／生成／成稿节点，支持增删、复制、拖动、类型端口连线、分支与汇合；提供城市灵感、完整行程、双方案比较、结构化行程、筛选与优化、候选池分日规划、按区域分日规划、多主题汇合规划八套可编辑模板，生成指令、温度与检索参数独立配置。运行目标及必要上游或运行全部，按真实输入和服务配置复用未过期产物；失败隔离、停止恢复、运行快照、草稿修订与JSON导入导出已接入。成稿可预览并采用为同一方案的新正式版本，保留既有实际记录与历史，设计与边界见 [节点工程设计](../../WORKFLOW_DESIGN.md)。

首版只读基础视图已完成：从原旅行进入，按真实编排展示需求／推荐、检索、生成、确认／修改四个节点，查看输入、输出与当前保留数据。行程、路线和预算是同一生成节点的输出，不冒充已经独立执行的节点。支持分支和版本切换、数据来源、真实中断的安全提示、固定版本导出及返回对应当前方案；不调用模型、不增加版本、不应用待确认操作，缺失过程记录时保留未知。

首批参数编辑与受保护的局部重跑已完成：选择一天、市内默认交通和优化要求，保留全部地点，只重排固定站点之间的未执行活动；预览前后顺序、整趟预计支出、未知费用与冲突，刷新恢复或丢弃，应用保存为新版本。既有执行记录、人工预算与交通关联、实际账目、预约和照片／回顾保留，其他天不变；版本或过程变化、待确认操作、已结束、固定交通未知或时间冲突时拒绝应用。

工程成稿的结构化预览与采用已完成：检查每日安排、需求、预算、新增／移除／调整／保留及冲突，确认后创建首版或更新同一方案。保护既有执行记录、消费及预算／照片关联、预约与旅中约束；拒绝旧基线及冲突，回复丢失重试复用结果，新旧引用衔接到后续对话。

首批结构化工具节点已完成：模型生成每日景点与日程数据，地图校验地点和交通，程序汇总分类预算；通过有类型的端口流转，侧栏展开或下载数据，核对同一路线与预算后成稿，采用时直接复用结构并保护原旅程。

个人命名模板与跨旅行复用已完成：保存当前工程的结构与参数，默认替换需求输入，可保留通用固定文字，支持搜索、改名说明、更新及删除；修订冲突拒绝覆盖，回复丢失可重试，载入只产生可撤销草稿，不携带运行或正式记录。

每日景点筛选及路线顺序参数已完成：数量上限、必去／排除和建议停留，输出逐项取舍；在固定站点间依据确认坐标减少折返，重查交通，完整地图结果变慢则退回，超时不采用部分结果；参数及记录接入模板、运行快照与受保护采用。

分类预算预留已完成：明确设置人天饮食、房晚住宿、往返交通与全团备用金，缺项补齐可核对，既有金额与未知分项保留；采用前结合实际记录和人工预算重算，确认后可在正式预算编辑。
