# FE-3 第二批：正式旅行工作区

沿用 [共享设计规范](design/SYSTEM.md)。本批将 D3 对话主导、M1 今日路线与 P1 景点小图接到正式前端；业务数据继续通过现有接口读取和保存，没有引入样稿内存数据替代正式行程。

## 已迁移的使用路径

- **电脑 D3**：对话占主列，输入区保持在对话底部；右侧行程独立滚动，并有今日路线／地图／费用直达入口。路线内部按容器宽度排版，避免在窄侧栏里因为整个窗口较宽又挤出两列。
- **手机 M1**：有每日行程时先看当前站与今日路线；底部导航直达今日、地图、费用或对话。新规划和没有每日路线的旧路书仍以对话开始，保留自动整理入口。顶部次要说明缩减，当前站操作在默认首屏可见。
- **同一份工作区**：导航滚动到既有区域，不靠卸载组件切换页面；未发送的对话、正在填写的实付及当前选择不会因为快捷导航被重置。消息只滚动自己的消息区，首次载入历史不会把手机今日路线拉走；键盘焦点和减少动画规则继续生效。
- **当前站**：旅行日期恰好覆盖浏览器本地今天时先选当天，否则沿用首个行程日。优先进行中，其次未开始的非上下文停留；完成／跳过成功后转向下一个待走点。主动选站后会把对应操作区带回视野。途中已记录的调整时刻优先于原建议时刻，时间说明仍保留在紧邻入口。
- **P1 真实地点资料**：复用原有图片接口与懒加载缓存，固定 64 × 56px 小图、等比裁切；原图通过原生对话框完整查看，限制在视口内，可用 Escape 关闭并返回焦点。横图、长竖图、方图不改变缩略图尺寸，加载中预留同尺寸位置。没有图片、请求失败或所有候选图片损坏时回落文字，释放图片位置；不会要求用户补图，也不再显示大块装饰占位。
- **版本与实际记录**：保留已有版本选择、分叉、导出、旅中状态、预约、跨天调整、账目与回顾。快捷跳转、选站与关闭参考图只影响界面；完成状态和实付继续走原有回执与保存逻辑。

主要文件为 `app/chat/[sessionId]/page.tsx`、`components/itinerary-panel.tsx`、`components/place-photo.tsx`、`lib/journey-view.ts`、`styles/journey.css`。已有行程但没有聊天历史时，界面提示继续修改现有行程，不重新要求填写旅行想法。没有改写用户／模型的历史文本，也没有将界面自己的警示 emoji 带入新样式。

## 验证与证据

```sh
cd frontend
npm run typecheck
npm run lint
npm run build
PLAYWRIGHT_BROWSERS_PATH=/tmp/travelflow-browser node node_modules/playwright/cli.js test --workers=1
```

类型、构建与格式检查通过；lint 0 错误、11 条既有警告。新工作区与无障碍定向检查 **22 项通过**。完整串行执行 **222 项**：首轮 219 项通过，另 3 项仅因装饰星号已移除或同时存在两个合法状态而定位失败；同步这些测试定位后，3 项复测全部通过（约 6.8 秒），保留草稿、实际保存和版本数量断言，未修改应用行为以绕过失败。

Windows Edge 对正式生产构建另外复核 1440／390 宽度：D3／M1、手机首屏当前站操作、地图／费用直达、对话与金额草稿保留均通过，未产生页面脚本错误。原始视口截图：[电脑](design/workspace/desktop-windows.png)、[手机](design/workspace/mobile-windows.png)；内容是隔离样本，不是用户旅行。验证后已关闭专用 QA 服务。

`journey-workspace.spec.ts` 新增 12 项桌面／手机检查，覆盖真实列宽与顺序、980／320 窄屏、消息载入不抢页面、导航与双份草稿保留、今天选择与完成后的实际记录、三种图片比例、对话框焦点和失败回落，以及无行程状态。原无障碍检查改为观察实际消息容器的 `scrollTo`，继续核对减少动画，而不是保留会把手机路线滚走的全页行为。

检查使用隔离 SQLite、固定服务替身与测试 SVG，不读取 `.env`，不发起真实地图／照片／模型请求，不接触个人数据。图片检查证明布局与失败处理，不能证明某个真实高德图片地址持续可用。正式浏览器测试串行运行，避开此前已观察到的隔离 SQLite 并发锁冲突。
