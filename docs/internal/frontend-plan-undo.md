# FE-3 第三批：对话规划的正式撤销

沿用 [R1 直接更新可撤销](design/SYSTEM.md)。本批接入正式版本与 checkpoint，不使用样稿的内存回退；D3／M1、C1 与 P1 继续沿用前两批。

## 使用方式

已有每日行程后，通过对话修改规划，消息区显示服务端已保存的变化：涉及哪几天、安排前后差异，以及“撤销这次规划修改”。用户不用另点采用，路线、预估与计划书随修改同步。

撤销会追加一个新版本，原修改与更早的历史仍可查看、分叉和导出。撤销结果写入对话，可接着提出新要求。未发送的聊天草稿保留；等待时显示“正在撤销并同步…”，暂时阻止同一工作区的并行写入；完成后焦点回到结果说明，减少动画设置继续生效。

初次生成、没有结构化每日行程的旧路书和历史版本不提供这个入口。当前批次只撤销最近一次**对话规划修改**；手动编辑和工程采用继续沿用各自的版本流程。后续另有规划编辑时，旧撤销不能覆盖新安排；刷新后以服务端重新核对的可用操作为准。

## 记录保护与重试

- 后来保存的消费、退款、报销、付款日期、凭证链接、回顾与照片选择保留。重新同步费用清单和导出正文，避免把旧实际总额带回来。
- 保留现有站点的最新进度，包括主动重置为“未开始”。如果恢复规划会移除或改变已经开始、完成或预约的站点，服务端拒绝直接撤销并说明原因，用户可继续用对话调整后续安排。
- 撤销携带当前版本、目标修改与独立请求号；服务端持有分支锁、核对最新版本及 checkpoint。其他窗口先保存时，旧操作原位报冲突，不覆盖已保存内容。
- 回包丢失后，当前标签页使用 sessionStorage 保留同一个请求号，刷新后可以“重试撤销”。已成功的请求返回同一结果，不重复生成版本；前端随后重读最新行程，不能用旧回执覆盖后来新增的消费。
- checkpoint 已写入而版本索引／正文尚未写完时，完成标记保留原结果。重试或下一轮对话可补齐同一版本；旧界面的写入不能盖过未完成撤销。SQLite 关闭重开也有隔离测试覆盖。
- 待确认的地点、记账或联动调整须先完成或取消，避免一次撤销暗中丢弃另一项待确认操作。读取修改记录失败不影响继续聊天，可原位重试。

恢复规划无需调用模型、搜索或地图，也不删除旧版本。现有真实记录与其凭证／照片资产均不因撤销而删除。

## 接口与实现

`GET /api/versions/{id}/planning-change` 只读推导最近一次可撤销的对话修改；消费和游玩进度不单独产生规划撤销。`POST /api/versions/{id}/undo-plan` 重新校验目标与版本，恢复规划和对应来源，在当前分支追加新版本及对话记录。不能由客户端任意指定一份历史快照覆盖整个旅行。

主要文件：后端 `services/plan_undo.py`，前端 `components/plan-change-notice.tsx` 与正式聊天页。完成标记新增在兼容旧数据的可选图状态中，无需清空或替换已有数据库。

## 验证

后端新增 16 项检查，包含真实对话修订、后续记账、回款与凭证保留、进度保留、版本冲突、跨分支、重复请求、部分写入失败，以及 SQLite checkpoint 重开恢复。特别核对正文尚未写入的版本不能在继续整理或分叉时被当成空旅行。完整后端 539 项通过；撤销服务 mypy 与本批 Ruff 检查通过。

前端新增 8 项桌面／手机专项检查：直接修改后的回执、草稿和焦点、等待反馈、回包丢失后刷新重试、后来消费保留、旧版本冲突与刷新、查询失败恢复及历史版本隔离。新版本读取稍迟于消息时，完成说明仍须可见；手机结果和输入框避开底部导航，初次进入仍保留 M1 顺序。类型与生产构建通过；lint 0 错误、11 条既有警告。最终构建完整串行浏览器回归 **230 项通过**。

Windows Edge 对最终生产构建另做 1440／390 视口实测，确认正式修改／撤销、只追加一次版本、原路线恢复、实付与回款保留、聊天草稿以及手机结果／输入框完整可见，未出现页面脚本错误。[原始截图与实测说明](design/undo/README.md)记录电脑和手机的修改前后；专用 QA 服务在验收后关闭。

所有测试使用临时 SQLite、固定模型与检索／地图替身，不加载 `.env`、不调用真实模型或高德服务、不接触个人旅行。检查证明正式接口和界面的集成行为，不证明真实服务商持续可用。
