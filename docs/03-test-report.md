## 6. 本轮发现并修复的缺陷

| # | 问题 | 影响 | 修复 |
| :--- | :--- | :--- | :--- |
| 1 | **分页 `total` 语义错误** | `total` 返回的是「本页数量」而非总数，超过 20 条时前端分页会算错 | 新增 `SessionStore.count_sessions()`，路由改用它 |
| 2 | 失败的一轮会留下半成品版本 | 版本树出现空白项，用户困惑 | 已有断言守住（本轮确认为既有实现正确，补测试固化） |

> 缺陷 1 由「50 个会话搜索」的规模测试暴露 —— 这正是全面测试的价值。

## 8. 移交阶段④的建议

1. **优先修复 Docker**：这是阶段④的核心交付（Docker 部署方式），需要先让 `docker info` 有响应；
2. **补真实链路冒烟**：拿一个真实 API Key，跑一次完整「输入 → 路书 → 导出」，确认假替身掩盖了真实差异；
3. 部署后验证清单：健康检查、前端可访问、导出可下载、配置页可保存、CORS 白名单与实际端口一致。
