### 路书档位设计（回应你的两点要求）

| 档位 | 篇幅公式 | 1 日游 | 3 天 | 7 天 |
| :--- | :--- | :--- | :--- | :--- |
| L1 极简 | `200 + 150×天` | 350 | 650 | 1250 |
| **L2 标准（默认）** | `400 + 350×天` | **750** | **1450** | **2850** |
| L3 详细 | `600 + 600×天` | 1200 | 2400 | 4800 |
| L4 保姆级 | `900 + 1000×天` | 1900 | 3900 | 7900 |

> ✅ **1 日游 750 字 vs 7 天 2850 字，差 3.8 倍** —— 篇幅随时长自然增长。
> ✅ 用户可在对话中随时切档，**切换产生新版本而非覆盖**，因此能「先生成极简版，再生成保姆级版做对比」。

## 二、你的三个新诉求 → 已设计

| 你的原话 | 设计响应 |
| :--- | :--- |
| 「用户很多时候可能自己并不明确需求」 | 多轮追问支持**局部重答**，不必重开对话 |
| 「绕了一圈可能更喜欢初版」 | **版本树 + 一键回退**：点任意历史版本「回到这里」，从该点开新分支，**原分支保留**可再切回 |
| 「面对选择可以通过分支直接对比多种规划」 | **分支对比页**：2~3 栏并排渲染 + 行级差异高亮 + 一键设为当前方案 |

**数据模型**：`sessions` / `branches` / `versions` 三张表 + LangGraph 自带 checkpoint 表，全部在同一个本地 SQLite 文件。

**技术前提已实测**：LangGraph 原生支持从任意 checkpoint 分叉（快照数 4→8，新链与原链共存，互不覆盖）。

## 四、验收标准（阶段③）

| 能力 | 验收方式 |
| :--- | :--- |
| 计划确认/修改闭环 | 第 2 轮说「改第二天」→ 只进 `refiner`，**不重新检索** |
| **版本回退可用** | 修改 3 轮后回退到 v1，内容与初版一致 |
| **分支可对比** | 同需求生成 3 个分支，并排展示差异 |
| 引用真实 | 文件里的 URL 全部来自检索结果，程序透传 |
| 篇幅随天数变化 | 1 日游与 7 日游篇幅差 ≥3 倍 |
| 并发不阻塞 | 3 并发总耗时显著小于串行 |
| 一键启动 | `./start.sh` 或 `docker compose up -d` |
| 模型可切换 | 改 3 行配置从 DeepSeek 切到本地 Ollama |
| 零成本可跑 | `SEARCH_PROVIDER=ddg` 无需任何 Key |
