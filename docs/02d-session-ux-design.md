## 2. 会话管理与分支对比（全新设计）★

### 2.1 你的诉求拆解

| 你的原话 | 隐含需求 |
| :--- | :--- |
| 「用户很多时候可能自己并不明确需求」 | 要允许**反复调整**而不必重开对话 |
| 「有时绕了一圈可能更喜欢初版」 | 需要**版本历史 + 一键回退到任意历史版本** |
| 「面对选择可以通过分支直接对比多种不同规划」 | 需要**从任意节点分叉（fork）** + **并排对比** |

→ 这本质上是把 Git 的**分支思想**引入对话式规划。不能只用「一条线性对话」。

### 2.2 概念模型

```
会话 Session「重庆之行」
│
├─ 分支 B1（主方案）
│    v1 需求收集完成 ── v2 检索完成 ── v3 标准版路书 ── v4 改轻松版
│                                            │
│                                            └──★ fork 点
│                                                 │
├─ 分支 B2（从 v3 分叉：改为"亲子版"）             │
│    v3' 标准版路书（继承）── v4' 亲子版路书 ◀─────┘
│
└─ 分支 B3（从 v3 分叉：改为"极简版"）
     v3'' 标准版路书（继承）── v4'' 极简版路书
```

**三个概念**：

| 概念 | 定义 |
| :--- | :--- |
| **Session（会话）** | 一个旅行主题，如「重庆之行」，对应一个 LangGraph `thread_id` 族 |
| **Branch（分支）** | 一条独立的规划演化线，可随时分叉与并行 |
| **Version（版本）** | 分支上的一个状态快照，可回退、可对比、可导出 |

### 2.3 分支的三种创建场景

| 场景 | 触发方式 | 例子 |
| :--- | :--- | :--- |
| **A. 回退** | 在版本树里点某个历史版本 →「回到这里」 | 绕了一圈发现初版最好 |
| **B. 多方案对比** | 信息收集完成后点「生成 3 个候选方案」 | 同样"重庆3天"，一个亲子版、一个美食版、一个极简版 |
| **C. 手动分叉** | 在任意版本点「从这里新建分支」 | 用户自己指定分叉点 |

### 2.4 数据模型（本地 SQLite 单文件）

> 遵循你的要求：**不用登录、不用服务端**，所有数据落在用户本机 `data/travelflow.db`。

```sql
-- 会话
CREATE TABLE sessions (
    id            TEXT PRIMARY KEY,          -- uuid
    title         TEXT NOT NULL,             -- 自动取目的地，可改
    created_at    TIMESTAMP NOT NULL,
    updated_at    TIMESTAMP NOT NULL,
    archived      INTEGER DEFAULT 0          -- 归档而非删除
);

-- 分支（一条演化线）
CREATE TABLE branches (
    id                  TEXT PRIMARY KEY,    -- uuid，同时作为 LangGraph thread_id 的一部分
    session_id          TEXT NOT NULL REFERENCES sessions(id),
    parent_branch_id    TEXT REFERENCES branches(id),   -- 血缘：从哪条分支分叉
    fork_checkpoint_id  TEXT,                -- 血缘：从哪个快照分叉
    fork_version_id     TEXT,                -- 便于 UI 展示
    title               TEXT,                -- 如"亲子版"
    is_primary          INTEGER DEFAULT 0,   -- 是否主分支
    created_at          TIMESTAMP NOT NULL
);

-- 版本（分支上的快照，供 UI 展示与回退）
CREATE TABLE versions (
    id               TEXT PRIMARY KEY,
    branch_id        TEXT NOT NULL REFERENCES branches(id),
    checkpoint_id    TEXT NOT NULL,          -- 对应 LangGraph checkpoint
    seq              INTEGER NOT NULL,       -- 分支内序号
    summary          TEXT,                   -- 一句话摘要，如"标准版路书已生成"
    detail_level     TEXT,                   -- 生成时的档位
    trigger          TEXT,                   -- user_message / fork / retry
    created_at       TIMESTAMP NOT NULL
);

-- 路书产出（一个版本可能对应一份路书）
CREATE TABLE plans (
    id          TEXT PRIMARY KEY,
    version_id  TEXT NOT NULL REFERENCES versions(id),
    markdown    TEXT NOT NULL,
    citations   TEXT NOT NULL,               -- JSON: [{index,title,url,retrieved_at,provider}]
    searched_at TIMESTAMP,                   -- 信息检索时间（时效性标注）
    created_at  TIMESTAMP NOT NULL
);
```

**LangGraph 的 checkpoint 表**（`langgraph-checkpoint-sqlite` 自带）与本表**共存于同一 sqlite 文件**：前者存完整状态，后者存用于 UI 展示的轻量索引。

### 2.5 技术实现（**已实测验证**）

**实测结论**：LangGraph 原生支持从任意 checkpoint 分叉。

```
历史快照可回溯：get_state_history() 返回 4 个 checkpoint (step 2/1/0/-1)
从最早快照 fork：invoke(新输入, {thread_id, checkpoint_id}) 
                → {'n': 111, 'log': ['FORKED','A','B']}
fork 后快照总数：4 → 8（新链与原链共存，互不覆盖）
```

**分叉的两种实现方式与选型**：

| 方式 | 做法 | 优点 | 缺点 | 选型 |
| :--- | :--- | :--- | :--- | :--- |
| 同一 thread 内多链 | `thread_id` 不变，指定 `checkpoint_id` 续跑 | 血缘天然存在 | `get_state()` 不指定 id 时"最新"语义含糊，易踩坑 | ❌ |
| **独立 thread + 血缘表** | 新分支用**新 `thread_id`**，从源分支某 checkpoint **拷贝状态**作为起点，血缘记在 `branches` 表 | 各分支完全隔离、语义清晰、易做并发 | 需要显式拷贝状态 | ✅ **采用** |

### 2.6 分支对比（核心体验）

```
┌─────────────────────────────────────────────────────────────────┐
│  对比：重庆3天方案                                    [设为当前]  │
├──────────────────────┬──────────────────────┬───────────────────┤
│  B1 标准版            │  B2 亲子版            │  B3 极简版        │
│  ─────────────────    │  ─────────────────    │  ──────────────   │
│  ## 交通建议          │  ## 交通建议          │  ## 行程          │
│  高铁二等座约 500 元   │  高铁二等座约 500 元   │  D1 解放碑→洪崖洞 │
│                       │  ★ 加婴儿车友好提示    │  D2 磁器口→索道   │
│  ## 每日行程          │  ## 每日行程          │  D3 涂鸦街→返程   │
│  D1 解放碑→洪崖洞     │  D1 动物园看熊猫 ★差异 │                   │
│                       │                       │                   │
│  共 1280 字           │  共 1650 字           │  共 420 字        │
└──────────────────────┴──────────────────────┴───────────────────┘
```

**对比能力**：
- 并排渲染 2~3 个分支的**同一版本序号**（或各自最新版本）
- **差异高亮**：行级 diff，相同内容灰显、差异内容高亮
- **一键设为当前方案**：选定后该分支成为主分支
- **导出对比报告**：把差异导出为 Markdown

### 2.7 典型交互流程（覆盖你的三个诉求）

```
需求不明确                       绕了一圈想回初版              面对选择要对比
     │                                 │                            │
     ▼                                 ▼                            ▼
多轮追问，每轮都可"撤销"        版本树列出 v1…v5              点"生成候选方案"
     │                          点 v1「回到这里」                    │
     ▼                                 │                      从同一 fork 点
 collector 支持局部重答               ▼                      并行生成 2~3 个分支
（不必重开对话）              创建新分支从 v1 继续                  │
                                     │                            ▼
                                     ▼                     并排对比 → 定稿
                              原分支保留，可再切回
```

## 4. 路书详细度档位与动态篇幅

### 4.1 四档定义

| 档位 | 名称 | 定位 | 篇幅公式 | 内容深度 |
| :--- | :--- | :--- | :--- | :--- |
| **L1** | 极简 | 只要骨架 | `200 + 150 × 天数` | 每日行程要点 + 关键避雷 |
| **L2** | 标准（默认） | 够用 | `400 + 350 × 天数` | + 交通方式、住宿区域、费用预估表 |
| **L3** | 详细 | 想省心 | `600 + 600 × 天数` | + 具体交通接驳、餐厅推荐、备选方案 |
| **L4** | 保姆级 | 完全不想操心 | `900 + 1000 × 天数` | + 时间点安排、购票指引、行李清单、应急预案、当地习俗 |

### 4.2 篇幅矩阵（直观对照你的诉求）

| 档位 | 1 日游 | 3 天 | 7 天 | 10 天 |
| :--- | :--- | :--- | :--- | :--- |
| **极简** | 350 | 650 | 1250 | 1700 |
| **标准** | 750 | **1450** | 2850 | 4400 |
| **详细** | 1200 | 2400 | 4800 | 6600 |
| **保姆级** | 1900 | 3900 | 7900 | 10900 |

> ✅ 完全满足你的要求：**1 日游 750 字 vs 7 天 2850 字，差距 3.8 倍**，篇幅随时长自然增长，而不是固定字数上限。

### 4.3 注入方式（Prompt 侧）

```python
DETAIL_LEVELS = {
    "L1_minimal":  ("极简",   lambda d: 200 + 150 * d),
    "L2_standard": ("标准",   lambda d: 400 + 350 * d),
    "L3_detailed": ("详细",   lambda d: 600 + 600 * d),
    "L4_butler":   ("保姆级", lambda d: 900 + 1000 * d),
}

target = DETAIL_LEVELS[level][1](duration_days)
prompt_vars["target_length"] = f"{int(target*0.85)}~{int(target*1.15)}"
prompt_vars["detail_name"]   = DETAIL_LEVELS[level][0]
```

Prompt 中追加：

```
【详细程度】{detail_name}
【目标篇幅】{target_length} 字 —— 必须落在该区间内，篇幅不足说明内容不够具体，超长则精简表述。

【本档位的内容要求】
{L1: 只写每日行程要点与关键避雷，不展开背景介绍
 L2: 增加交通方式、住宿区域建议与费用预估表
 L3: 增加具体交通接驳方案、每餐推荐、每站备选方案
 L4: 增加时间点安排、购票与预约指引、行李清单、应急联系方式、当地习俗提醒}
```

### 4.4 档位不只是字数

除了篇幅，**内容结构也随档位变化**：

| 章节 | L1 | L2 | L3 | L4 |
| :--- | :-: | :-: | :-: | :-: |
| 行程概览 | ✅ | ✅ | ✅ | ✅ |
| 每日行程 | ✅ 要点 | ✅ | ✅ 分段 | ✅ 分时段 |
| 交通建议 | 仅往返 | ✅ | ✅ 含接驳 | ✅ 含购票 |
| 住宿推荐 | ❌ | ✅ 区域 | ✅ 区域+价位 | ✅ 具体清单 |
| 费用预估 | ❌ | ✅ 双档表 | ✅ 明细表 | ✅ 逐项+备用金 |
| 避雷贴士 | ✅ | ✅ | ✅ | ✅ |
| 备选方案 | ❌ | ❌ | ✅ | ✅ |
| 行李清单 / 应急 | ❌ | ❌ | ❌ | ✅ |

> 用户可在对话中随时切换档位 → 触发**新版本**（而非覆盖），因此可以"生成了极简版后，再生成保姆级版做对比"。

## 5. 导出设计（Markdown + 精美 HTML）

### 5.1 Markdown

纯文本，结构即第 4 章所述章节；引用以 `[1][2]` 标注 + 末尾附录列出真实链接（程序拼接）。**无动画、无样式**，适合二次编辑。

### 5.2 HTML：图文并茂 + 动画 ★

> 🎨 **效果原型已产出** → [`docs/prototype/report-preview.html`](prototype/report-preview.html)
> 用阶段①考古出的**真实路书数据**做的高保真预览，浏览器直接打开即可看到全部动画。
> 实测：**21 KB 单文件、零外部依赖**、含打印样式与 `prefers-reduced-motion` 降级。

**必须是单文件、离线可用**（内联全部 CSS/JS，不引用任何 CDN）。

**视觉结构**：

```
┌──────────────────────────────────────────────┐
│  渐变封面：重庆 3 天 2 夜                      │
│  预算 ¥2000 · 3 天 · 2 人 · 标准档             │
│  信息检索时间：2026-10-11 15:32                │
├──────────────────────────────────────────────┤
│  ① 行程总览  —— 卡片组（每张一天，悬停浮起）    │
│  ② 每日行程  —— 竖向时间轴，节点依次点亮        │
```

**动画清单**（纯 CSS + 少量原生 JS，无框架）：

| 顶部进度条 | 页面滚动 | `scroll` 事件计算百分比 |
