# TravelFlow 前端设计规范

2026-10-28，四轮选型、FE-3 主要页面及 FE-4 本轮收口已完成。用户确认记录以根目录 [DESIGN_BRIEF.md](../../DESIGN_BRIEF.md) 为准；本文件承载后续组件和页面迁移基线，不能将选型完成当成全站验收完成。

## 共享变量

使用语义变量表达页面背景、纸面、浮层、正文、次要文字、边界、强调色及状态，禁止在新业务页面另造一套颜色。A 的基线来自第三、四轮样稿：背景 `#e8e5de`、纸面 `#f8f5ee`、内容面 `#fffdf8`、正文 `#292e29`、次要文字 `#687064`、边界 `#d9dbcf`、强调色 `#355744`、强调浅底 `#e5ebdf`。

B／C 替换同一批颜色变量，不另建导航和组件。设置中的外观主题即时生效，当前浏览器按同源存储，并支持标签同步和首屏恢复；默认 A，不随系统偏好自动切换。主题与服务配置、草稿和旅行版本独立，浏览器拒绝保存时必须明确说明，不能把临时切换当作已持久化。

正式页面使用 `bg-paper`／`bg-surface`、`text-ink`／`text-muted`、`border-line` 及 accent／warning／danger 等语义工具类，或同名 `--tf-*` 变量。配色与主题样本统一维护在 `styles/tokens.css`；新增界面运行 `npm run check:design`，共享样式与主题相关修改同时核对三主题和两端。CI 执行同一检查，不再通过临时覆盖旧颜色类适配深色。

正文沿用系统中文无衬线栈，不依赖远程字体。对话正文及对话输入框 16px，配置字段电脑 14px／手机 16px，主标题约 24px／手机 22px，区块标题 18px，次要信息 12–13px；信息不能只靠颜色表达。后续针对真实页面调整层级时，优先补共享规范，不通过每页零散指定字体解决。

间距以 4px 为步进，常用 8／12／16／24／32px；面板内距电脑约 24px、手机约 18px。圆角默认 8px；时间线节点、地图点位可保持语义所需的圆形。避免巨幅渐变、等权卡片网格和无意义装饰。

## 交互状态

- 普通按钮、图标按钮、按钮式链接均有悬停、按下、焦点、禁用和等待状态。C1 悬停约 160ms，按下约 100ms；轻抬约 1px、按压缩至约 0.975。主按钮采用实色强调，不使用旧的蓝绿渐变。
- 图节点、地图点位等空间对象保留颜色／边界反馈，避免位移或缩放改变交互坐标与连线。共享组件为此保留空间操作变体。
- 减少动画时停止位移／缩放与持续旋转，保留状态文字和边界反馈。键盘焦点清晰，触屏无需悬停也能找到入口。
- 加载立即反馈并防止重复提交，成功以真实回执为准；失败保留草稿和已有结果，重试保持原有幂等语义。不能把动画当作请求成功。
- 实付、预估、预算余量／超额在同一项目与上下文呈现。金额使用已有整数分与服务端口径，样稿计算不可代替正式账目规则。
- 产品编写的界面不出现 emoji，沿用 Lucide；不清洗用户输入、历史对话、照片或模型原始内容。

## 普通子页面与配置

入口、旅行列表、设置与偏好复用 `styles/pages.css` 的页面、字段、分区和列表规则，沿用共享按钮、状态和卡片。手机输入字号至少 16px，长下拉选项、旅行名和备注在容器内收缩或换行。设置采用显式标签，输入标签不包含说明链接和其他按钮；分区直达保持同一份表单草稿。

编辑草稿与当前已保存内容分开表达。保存、删除、刷新各自显示等待，失败及冲突就近反馈，重试不丢输入；配置确认保存后才清空密钥新值，留空保留已有值。状态刷新不能覆盖用户后来输入的草稿。常用偏好仍由新旅行主动选用，不能因改版而默认勾选。

## 比较与使用指南

比较和指南复用 `styles/reference.css` 与普通子页面基础。电脑按所选方案并排，手机采用页面纵向阅读、方案跳转和返回选择；不将三列强行缩入窄屏。各分支分别加载与重试，已读正文不因其他分支失败或切换主方案重置。继续编辑携带分支来源，主方案切换不生成新版本；跨旅行迟到响应必须隔离。

使用指南按旅行阶段组织入口，常见问题保留原生键盘折叠、悬停／按下、焦点和减少动画。生成、采用、保存及外部服务状态分别说明，不用固定耗时或绝对可靠性作承诺。外链说明新窗口，服务配置以已保存内容为准。

## 回顾与照片

回顾、生涯和照片复用 `styles/history.css` 与 `RecapImage`。预览框尺寸稳定，窄编辑区按实际容器宽度排列；完整照片按保存图像比例展示并受视口高度限制。缺图或损坏回落文字并允许重试，关闭后焦点返回原入口。图片与上传按钮同样遵守 C1 和减少动画规则，用户照片与说明原文保留。

长回顾表单提供就近可见的保存区，等待、失败和确认回执跟随原操作，版本更新不静默丢掉结果。同版本刷新保留用户后来输入的新草稿；新版本仍按版本边界加载。照片选择、AI 生成与采用、正式保存分别说明状态，沿用现有来源指纹、记录和并发保护。

## 高级工程

W1 电脑默认画布与右侧检查区并排，长参数在检查区内部滚动；操作栏保留保存、运行、停止与原位反馈。检查区的“参数／产物”为定位入口，保留同一份表单、候选选择和产物内容。手机提供画布、检查区和工具箱直达，不在选中／拖动节点时自动跳走。

端口类型使用共享变量 `--tf-port-text`、`--tf-port-sources`、`--tf-port-candidates`、`--tf-port-itinerary`、`--tf-port-budget`；A／B 使用深色描点，C 使用对应浅色，保持对比。颜色辅助区分类型，输入／输出名称与类型校验仍须保留。节点和端口的反馈只改变绘制样式，不能修改坐标变换；连线焦点须有颜色以外的反馈。

工程控件与绘图端口分别处理：普通触屏控件保留 44px 命中区，随缩放的绘图端口提供聚焦、缩放和大尺寸键盘连接器作为替代。运行记录等长选项必须在容器内收缩；弹窗按实际视口限定边界，不能用被内容撑宽的页面宽度判断手机可用性。

## 迁移批次与完成边界

1. **共享基础**：语义 token、C1 按钮／卡片／反馈、应用外壳。保留现有组件参数与请求状态，先核对加载／失败／禁用和移动端。
2. **普通旅行**：D3／M1 布局、对话与路线联动、R1 正式应用／撤销、原位费用、P1 图片与地图。保留历史版本、实付、自定义项和草稿。
3. **高级工程**：W1 检查区与统一样式，保留现有节点类型、端口校验、分支、模板、产物和运行恢复。
4. **全站收口**：主题设置与持久化、剩余设置／列表／生涯／回顾／帮助等页面，以及原生按钮与按钮式链接、无 emoji 和全部状态的统一检查。

共享组件迁移完成不意味着原生按钮、旧硬编码颜色、D3／M1、R1 或 W1 已全部落地。各批提交记录实际覆盖页面、验证结果与剩余事项；业务路径继续使用正式后端与隔离测试数据验证，不读取或改写个人旅行数据。
