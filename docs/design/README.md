依据 [设计约定](../../DESIGN_BRIEF.md)。当前只有使用方式和四项基本要求已确认；A/B/C 及密度 1/2/3 均待用户选择。预览默认 A＋2 是推荐起点，不是正式批准。

## 试用样稿

从仓库根目录运行：

```sh
python3 -m http.server 4387 --bind 127.0.0.1 --directory docs/design
```

在本机打开 [视觉方向预览](http://127.0.0.1:4387/visual-directions.html)。可切换风格、密度与电脑／手机尺寸，试按保存、调整、记账、日期和路书按钮。所有数据与结果都只在样稿内演示，不读取环境文件、不请求模型、地图或项目后端，也不保存最终设计投票；用户在对话中的选择才进入设计记录。

图标从项目现有 `lucide-react` 渲染并保存在 `icons.js`，无需外部请求。湖面与路线只是版式示意，不是可导航的实际地图。界面没有 emoji，控件的悬停、按下、焦点及等待状态可实际检查；减少动画设置下保留静态反馈。

## 验证与边界

```sh
cd frontend
PLAYWRIGHT_BROWSERS_PATH=/tmp/travelflow-browser node scripts/check-design-preview.mjs
```

浏览器脚本使用临时本机端口并在完成后关闭，检查三个方向、三种密度和 1440／390／320 宽度，共 27 种组合；核对实际悬停与按下、异步演示反馈、修改与记账表单、触屏高度和减少动画，生成六张原始截图与 [检查结果](preview-check.json)。它不等于正式应用改造验收，本轮没有修改产品页面与业务数据。
