# 普通用户少操作验收：选城承接与对话恢复

2026-10-28，前端升级收口后的第一批主流程走查。沿用已确认的 D3／M1、C1／P1、R1／W1 与三主题，不增加节点或设置。

## 本批发现与修复

### 选过城市却又被推荐一轮

旧 collector 对每条消息都重新调用字段提取模型。已保存城市候选后，用户回复“第二个”，若模型漏掉 destination，程序会再次推荐，用户还得再选一次。用旧提交和漏提取替身已复现此路径，原来的理想模型测试不能发现它。

现在对已保存候选和明确短选择直接承接：序号、中文数字、全角数字，以及“就选成都吧”等城市名表达可进入下一步，保留原预算、日期、人数和偏好，不额外调用字段提取模型。序号越界只说明现有候选，不重排或重新检索，不生成空版本。该承接只在其余必填条件齐全、目的地尚未确定时使用；预算等复合修改仍走完整语义提取，不丢附带条件。询问、否定和多城市比较不强行套成短选择。

模型返回空白、重复城市时先整理可用项；若没有可用候选，按既有 `LLM_OUTPUT_INVALID`／422 返回可重试错误，不输出一份空列表让用户继续选择。原请求重试后沿用已有出行条件，真正选定后才生成计划。后续检索与规划仍需要相应服务，不把“少一次字段提取调用”说成无需模型。

### 历史读取失败看起来像刚开始

旧前端在历史读取失败时清空消息并吞掉错误，用户刷新后容易误以为需要重新讲需求。现在在对话区原位显示等待、失败与重试，保留已显示内容和输入，不在读取未完成或失败时显示新对话引导。

读取请求按分支和消息修订隔离，迟到快照不能覆盖新发送的内容；切换分支保留该分支合法继承的历史，不混入旧分支迟到的内容或路书。历史重试只读对话，不额外读取路书，不触发再次发送或保存。等待期间仍可继续输入、发送，反馈遵守共享样式与手机宽度。

## 已走通的任务

1. 从上海出发、三天、少走路，先请求城市推荐；补预算后直接给候选，不再问需不需要推荐。
2. 刷新后回复短序号；越界时保留候选，选定后形成每日行程。
3. 一条对话记录完成状态和 86.35 元实付，再修改第一天的安排，实付保留。
4. 主动打开回顾、编辑自己的文字、保存并结束旅行；原版本、实际消费和用户原文保留。
5. 从回顾阅读页查看记录并导出，阅读与导出不增加版本。

这条路线使用固定模型与真实本地编排、持久化及导出接口，证明操作承接与数据一致性；不评判真实模型所生成景点的质量或外部服务可用性。回顾仍是可选操作，打开、采用和保存的边界没有被自动化代替。

## 2026-10-29 接续：条件摘要与路书读取恢复

核对 `3e67c3f` 交接基线、干净工作区与实际源码后，支持现有路线：主体功能已经覆盖旅前、旅中和旅后，接下来优先修复普通用户主流程中的上下文断点与失败恢复。不重新选择前端风格、架构或扩充高级节点。

生成前右侧现集中显示出发地、天数、预算及已提取的其他条件、真实缺项、保存阶段和城市候选。摘要来自当前分支 checkpoint 的公开字段，普通与流式回复同步携带；刷新读取不调用模型或产生版本，不解析聊天文字推测状态。日期、人数和预算口径留空时不填默认值，零元预算保留；已要求推荐时不把目的地再列为必须先填的条件。旧客户端与没有摘要的旧请求回执继续兼容，后者重放后由历史接口恢复当前摘要。

路书独立区分没有版本、读取中与读取失败，失败就近提供重试，不再显示成没有计划。后台失败保留同分支已读内容和同版本费用表单草稿，切换分支不显示旧路书；历史选择仍只读，迟到的较新版本不会覆盖后选的旧版本。重试路书不重读对话、不重新生成、不写版本。手机已有计划但读取失败时，恢复区域优先出现在首屏，「今日」可直达恢复位置；读回后继续原 M1 路线布局。

本批验证使用临时数据库、固定模型／检索／地图替身；后端相关专项 **37 项通过**（新摘要场景6项，加选城与请求重试回归），类型检查通过116个源文件，Ruff及应用格式检查通过。没有重跑上一轮564项后端全量。

最终构建上，浏览器对主流程、历史、消息恢复、费用、工作区和规划撤销运行 **80 项双端回归通过（1.6分钟）**，其中新增 `planning-recovery.spec.ts` 的16项覆盖条件展示、草稿、旧响应、分支、历史和三主题恢复。迟到响应明确等待回包后断言；手机恢复区域通过首屏视口断言及截图核对。截图由专项测试保存到忽略的 `frontend/test-results/`，可重复生成，不作为持久交接材料。没有重跑上一轮330项浏览器全量。

本环境默认 Turbopack 构建受本地端口权限限制，申请本机执行后仍失败；改用 Next.js 自带的 `pnpm exec next build --webpack` 完成生产构建，没有更改依赖或默认构建脚本。TypeScript 与 `check:design` 通过，ESLint为0错误、11条既有警告。专用测试服务随测试结束关闭。未调用真实外部服务，未做Windows原生复核、真实手机或多日实走，未发布部署。
